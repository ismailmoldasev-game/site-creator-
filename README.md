# Site Studio

Персональный визуальный конструктор сайтов. Главная страница всегда открывает **настройки проекта** с кнопкой **«Конструктор сайта»**.

## Возможности

- Страницы, общие шапка и подвал, библиотека из 9 типов секций, копии, скрытие, удаление и перетаскивание.
- Боковая панель редактируемых полей. Все экземпляры блоков имеют независимое содержимое.
- Реальные viewport 390 / 768 / desktop, масштабируемые под рабочую область. Мобильные панели и кнопки перемещения.
- Общие цвета, шрифты, логотип, favicon, ширина содержимого и скругления. Четыре палитры.
- Серверное автосохранение в D1, оптимистическая блокировка по revision, локальная аварийная копия несохранённых изменений, undo/redo.
- Контрольные версии и восстановление с предварительным сохранением текущего черновика.
- Генерация HTML/CSS-блоков через OpenAI. Блок получает схему полей, сохраняется в библиотеке, при подключённом GitHub автоматически записывается в код.
- Экспорт проекта JSON и ZIP готового статического сайта без зависимостей от конструктора.
- Синхронизация проекта в GitHub и публикация в отдельную ветку GitHub Pages. Домен, DNS-проверка, состояние сборки.

## Технологии и структура

React + TypeScript, Vinext / Vite, Cloudflare Worker и D1. Стандартные сайты экспортируются в обычный HTML/CSS. ИИ работает по HTTPS API, ключи хранятся в D1 только в зашифрованном виде (AES-256-GCM с отдельным серверным ключом).

## Запуск

Требуется Node.js 22.13+ и pnpm. Менеджер пакетов и версии закреплены lock-файлом.

```sh
pnpm install --frozen-lockfile
pnpm build
```

Для первого локального запуска примените миграцию:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_furry_inhumans.sql
pnpm dev
```

В среде ChatGPT Sites используйте штатные команды запуска и публикации Sites. Локальная и рабочая базы независимы; тестовые данные не переносятся при развёртывании.

## Ключ шифрования

В рабочей версии настроен секрет `STUDIO_ENCRYPTION_KEY`. Для отдельной установки создайте собственный 32-байтный ключ в base64 и задайте его как серверный секрет. Пример генерации:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Для локальной разработки допускается незакоммиченный `.dev.vars`. Нельзя менять ключ шифрования без миграции сохранённых подключений: старые зашифрованные ключи станут недоступны. Значения ключей не входят в GitHub, клиентский bundle или экспорт проекта.

Рабочий редактор размещён как приватный Site с авторизацией платформы. При отдельном развёртывании серверных маршрутов нужна равнозначная защита всего редактора и `/api/*` (например, Cloudflare Access). Настройки GitHub Pages предназначены для **экспортируемого сайта**, а серверный редактор требует Worker и D1.

## Подключение GitHub

В настройках выберите «Подключения», укажите `owner/repository` и Fine-grained Personal Access Token с доступом к этому репозиторию:

- Contents: Read and write.
- Pages: Read and write.
- Репозиторий должен иметь начальный коммит (например, README).
- GitHub Pages должен быть доступен на текущем тарифе для выбранной видимости репозитория.

Данные проекта и код пользовательских секций сохраняются в ветку `studio-content`, папку `studio-content/`. Это отдельная ветка, её коммиты не публикуют сайт. Готовые HTML-страницы публикуются в `gh-pages`. Ветки `main`, `master`, `studio-content` защищены от использования в качестве выходной ветки публикации.

GitHub-коммит атомарный, обновление ссылки без force. Изменение ветки другим клиентом приводит к отказу записи вместо потери чужих коммитов. Начальный код редактора загружается в отдельный репозиторий независимо от синхронизации его контента.

## Подключение ИИ

В «Настройки → Подключения» добавьте OpenAI API-ключ и доступную модель с поддержкой Chat Completions и JSON mode. Баланс API отдельный от подписки ChatGPT. До подключения генератор показывает необходимое действие; демонстрационные ответы не используются.

Генератор создаёт HTML/CSS-секции с полями `text`, `textarea`, `url`, `image`. Проверяются JSON-схема, имена полей и отсутствие активного кода. Скрипты, формы, SVG и внешние стили не поддерживаются. Предпросмотр находится в sandbox iframe; содержимое экранируется, экспорт получает CSP без скриптов. Ошибка синхронизации с GitHub не удаляет уже созданный блок: его можно записать повторно кнопкой синхронизации.

## Данные и развитие

`schemaVersion: 1` позволяет добавлять миграции структуры проекта. D1 хранит одну рабочую запись проекта и отдельные версии. `revision` предотвращает перезапись из старой вкладки; при конфликте интерфейс предлагает скачать локальную копию и загрузить актуальное состояние. Шапка и подвал общие для страниц, содержимое каждой секции независимо. Фотографии уменьшаются в браузере до 1280px и сохраняются внутри проекта, поэтому перенос сайта не зависит от приватного файлового сервера.

В текущей версии — одно персональное рабочее пространство, максимум 30 страниц, 80 блоков на страницу, 100 своих шаблонов и 4 МБ на запрос сохранения. Серверное автосохранение не запускает публикацию. DNS проверяется отдельно; наличие CNAME/A-записей не означает готовность HTTPS.

## Проверки

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm format
```

Браузерная проверка: стартовые настройки, изменение и перезагрузка, редактирование блока, добавление и undo, новая страница, общая палитра, контрольная версия, конфликт двух вкладок, мобильный редактор. Внешние генерация и публикация требуют собственных подключений; без действующих ключей их сквозная проверка не выполнялась.

## Адрес GitHub Pages

[Открыть Site Studio](https://ismailmoldasev-game.github.io/site-creator-/).

GitHub Pages публикует только страницу входа из `pages/`, которая через три
секунды переводит на существующий рабочий редактор
https://site-studio-ismail.ismail-moldashev.chatgpt.site/.
Есть и обычная ссылка для ручного перехода. Авторизация редактора сохраняется;
исходники, данные проектов и ключи не входят в артефакт Pages.

Публикация настроена в `.github/workflows/pages.yml`: изменения `pages/**`
в ветке `main` и ручной запуск workflow загружают отдельный статический артефакт
и развёртывают его официальными Actions GitHub Pages.
В **Settings → Pages → Build and deployment → Source** должен быть выбран
**GitHub Actions**. Другие ветки и корень исходников не используются как сайт.

Сам редактор использует Vinext/Vite, Cloudflare Worker, D1 и серверные маршруты
`/api/*`. GitHub Pages обслуживает статические файлы и не запускает эту
серверную часть. Поэтому `pnpm build` и папка `dist/server` не используются
в этом workflow. Настройка Vite `base` здесь не требуется: страница входа
самодостаточна и работает по пути `/site-creator-/`, а редактор остаётся
на своём исходном домене с прежними API и авторизацией.

Если адрес редактора изменится, обновите URL в `pages/index.html`
(перенаправление, canonical и ссылка) и эту документацию.

## Личные аккаунты и доступ

Конструктор использует Sign in with ChatGPT на хостинге Sites. Первая авторизация автоматически создаёт личный аккаунт. Отдельные пароли приложение не хранит. Публичный режим Sites открывает страницу входа, а сервер проверяет личность для каждого запроса к редактору.

- В production настройте секрет `STUDIO_LEGACY_OWNER_EMAIL` на подтверждённый адрес владельца Sites. Значение не хранится в репозитории. Только эта подтверждённая личность может получить прежний проект `main`. Уникальная связь с постоянным ID сохраняется в `studio_accounts`; регистрация постороннего первой не передаёт ему проект.
- Миграция `0001` добавляет таблицу аккаунтов и принадлежность истории. Документ существующего сайта, его ревизия, изображения и зашифрованные подключения остаются на своих местах. Старые версии относятся к `main`.
- Страницы, история, экспорт, подключения GitHub / OpenAI, генерация и публикация используют пространство текущего аккаунта. ID из JSON или URL не выбирает владельца.
- Заголовок `X-Studio-Account` должен совпадать с проверенной личностью Sites. Это защищает от сохранения из старой вкладки после смены аккаунта. Сам заголовок не является авторизацией. Сервисный токен Sites без личности пользователя доступа к редактору не даёт.
- Локальные страховочные копии разделены по ID аккаунта. Прежняя копия `studio-recovery` восстанавливается только владельцу `main`. При выходе приложение сначала сохраняет правки; при ошибке предлагает скачать их.
- `/preview` и `/*.html` на адресе конструктора — закрытые предпросмотры черновика. Публичные файлы создаются отдельно функцией `publicSiteFiles`, без `project.json` и исходников библиотеки блоков. Файл проекта включён только в закрытый резервный экспорт.
- GitHub Pages не исполняет сервер конструктора. Папка `pages/` в GitHub содержит входную страницу, которая может ссылаться на защищённый редактор. Готовый сайт публикуется отдельно в ветку, указанную в настройках, или через HTML-экспорт. Для реальной публикации нужно заполнить репозиторий и подключение.

Не размещайте Worker напрямую на другом хостинге, доверяя произвольным `oai-authenticated-*` заголовкам. Здесь их устанавливает проверяющий запросы шлюз Sites. При смене хостинга потребуется собственная проверенная авторизация.

Проверка `npm test` включает реальные обработчики API с отдельной тестовой SQLite-базой, проверку анонимного доступа, изоляцию двух аккаунтов, секретов и истории, смену аккаунта и сохранность старого проекта после миграции.
